# LBC-004 · On-chain command and configuration retrieval

Evidence: **Observed** · Reviewed 2026-10-15
Chains: Polygon · Networks: Mainnet, Testnet

Contract state carries instructions that infected devices retrieve and interpret.

## Analysis procedure

### Collect

Polling requests, returned command/configuration bytes and module handling code.

### Inspect

Recover command boundaries, encryption and task selection from the sample; compare responses at incident-time blocks.

### Correlate

Link an identified task to process, file or command-result evidence. Preserve unexecuted tasks separately.

### Interpretation limits

Configuration reads do not prove all modules or commands ran. Do not reclassify a URL-only resolver as a command channel.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

Aeternum retrieves encrypted commands through Polygon RPC. REVSTEALER modules retrieve replaceable settings; one getter supplies mining command-line arguments. These are instruction/configuration reads, distinct from a getter that returns only a C2 URL. Published code configuration does not prove every branch ran.

Examples: Aeternum; REVSTEALER module configuration

### Detection guidance

Correlate repeating eth_call traffic, contract addresses and execution of downloaded components.

### Defensive approach

Control RPC egress and investigate loader persistence. Provider blocking alone will not remove the contract.

## ATT&CK assessment

Enterprise · Technique · Reported behavior

The documented contract read delivers instructions to the implant. No return output over the same contract read channel is established; a domain-pointer-only variant would fit Dead Drop Resolver instead.

- [TA0011 · Command and Control](https://attack.mitre.org/tactics/TA0011/)
- [T1102.003 · Web Service: One-Way Communication](https://attack.mitre.org/techniques/T1102/003/)
