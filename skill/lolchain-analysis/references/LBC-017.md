Evidence: **Observed** · Reviewed 2026-10-15

An embedded proxy carries malicious traffic through TON’s encrypted overlay.

## Analysis procedure

### Collect

Android/app artifacts, .adnl destination, local TON proxy configuration and session telemetry.

### Inspect

Trace the app-to-local-proxy-to-overlay route; keep pseudo-hostnames and native peer identifiers intact.

### Correlate

Match remote-control or upload activity to screen/file/network evidence from the device.

### Interpretation limits

Do not put .adnl identifiers in ordinary DNS hostname blocklists. This is distinct from TON smart-contract resolution.

Methods: [NKN and TON transport](overlays.md).

## Catalog context

ThreatFabric documents .adnl destinations routed through a local TON proxy, alongside remote-control and file-upload capabilities. The pseudo-hostnames are not ordinary DNS records.

Examples: TrickMo variant C

### Detection guidance

Inspect Android app provenance, native proxy components and unexpected TON flows. DNS-only blocklists cannot cover ADNL identities.

### Defensive approach

Use mobile endpoint controls and application-aware egress policy. There is no complete static list of TON peer IPs here.
