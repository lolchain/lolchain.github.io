# LBC-001 · Smart-contract payload hosting

Evidence: **Observed** · Reviewed 2026-10-16
Chains: BNB Smart Chain, Base · Networks: Mainnet, Testnet

Encoded loader code lives in contract state and is retrieved by a browser or downloader.

## Analysis procedure

### Collect

Captured loader, contract, selector/arguments, chain/network and returned bytes.

### Inspect

Reproduce the getter at the incident block; ABI-decode the returned string/bytes, then preserve each script decoding layer.

### Correlate

Match the recovered script hash or content to browser cache, injection and subsequent network/process activity.

### Interpretation limits

If only a URL is returned, classify that step as LBC-003. A reader does not appear as a ledger transaction.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

Public reports describe JavaScript stored in BNB Smart Chain and Base contract state and retrieved by browser loaders. Mainnet and testnet examples are documented. A getter that returns only an off-chain URL is address resolution (LBC-003), not payload hosting.

Examples: ClearFake / EtherHiding; BSC-testnet browser staging

### Detection guidance

Correlate unexpected RPC reads with script execution, redirects and browser child processes. eth_call reads are visible to the RPC provider, not recorded as transactions.

### Defensive approach

Restrict unsanctioned RPC egress, review web scripts and browser service workers, and block confirmed downstream delivery resources.

## ATT&CK assessment

Enterprise · Technique · Reported behavior

On-chain malware staging fits Upload Malware; fetching a subsequent payload into the victim environment fits Ingress Tool Transfer. Hosting a fake CAPTCHA alone does not establish User Execution.

- [TA0042 · Resource Development](https://attack.mitre.org/tactics/TA0042/)
