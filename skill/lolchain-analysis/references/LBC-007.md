## Analysis procedure

### Collect

Wallet/block scan, selected transfer, sender/recipient bytes and loader selection code.

### Inspect

Determine whether the sample scans blocks or outbound zero-value transfers; decode only the selected recipient bytes.

### Correlate

Match the reconstructed destination to a contacted server and the sample’s other recovery routes.

### Interpretation limits

This need not involve a contract. Wallet activity is signaling evidence, not an infection count or automatic ownership proof.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

Recipient bytes encode a downstream address. HashHiding scans Ethereum blocks alongside the RAT’s parallel recovery routes; NullReceiver selects an outbound zero-value transfer and decodes its recipient. Neither requires a smart-contract payload. Transaction totals are signaling activity, not infection counts.

Examples: XCTDH / HashHiding; NullReceiver npm loaders

### Detection guidance

Hunt eth_getBlockByNumber and eth_blockNumber from unexpected Node.js processes, followed by direct-IP HTTP traffic.

### Defensive approach

Monitor both chain reads and resulting C2 connections; cover fallback channels during containment.
