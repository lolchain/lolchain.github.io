# LBC-024 · Arweave-backed configuration recovery

Evidence: **Implemented** · Reviewed 2026-10-15
Chains: Arweave · Networks: Not applicable

A decentralized storage query can recover configuration for off-chain C2 transports.

## Analysis procedure

### Collect

Arweave query/tags, selection logic, returned transaction/data-item ID and encrypted configuration.

### Inspect

Recover the selected data from preserved responses; apply the sample’s keys and decode sequence.

### Correlate

Establish whether the Arweave branch ran and connect the recovered transport settings to host activity.

### Interpretation limits

The cited intrusion did not confirm runtime use. Code connected to a sample is not proof of execution in that incident.

Methods: [IPFS, IPNS and Arweave](content.md).

## Catalog context

The DFIR Report found connected TukTuk code that queries Arweave by Drive-Id and retrieves encrypted transport configuration. The investigators did not confirm use of this capability during their intrusion.

Examples: TukTuk; runtime use unconfirmed in cited intrusion

### Detection guidance

Review Arweave gateway access from unexpected processes and correlate subsequent SaaS connections.

### Defensive approach

Baseline the gateways; use malware and process evidence to assess intent. Treat this as an implemented fallback, not confirmed observed traffic in that incident.
