## Analysis procedure

### Collect

NKN send events, client/recipient identity and locally collected screenshots, output or system information.

### Inspect

Map serialized message fields to local artifacts; keep encryption/key provenance and message direction.

### Correlate

Correlate a specific send with data collection, process context and connection timing/volume.

### Interpretation limits

Code capable of sending data is not proof of a completed transfer. Do not claim public-chain storage of overlay messages.

Methods: [NKN and TON transport](overlays.md).

## Catalog context

NKAbuse returns screenshots, heartbeat and command output over NKN. AhnLab also documents NKNShell sending system information through NKN and an independent MQTT path. Overlay messages do not imply public ledger storage.

Examples: NKAbuse; NKNShell

### Detection guidance

Correlate screen capture or collection behavior with NKN-enabled processes and outbound peer traffic.

### Defensive approach

Contain the endpoint and its NKN client; shared relay blocking should be driven by business policy.

## ATT&CK assessment

Enterprise · Technique · Reported behavior

NKAbuse returns screenshots, host information and command results over its existing NKN C2 channel. Data is not necessarily written to a blockchain ledger.
