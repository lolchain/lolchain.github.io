# LBC-028 · Contract-routed payment skimming

Evidence: **Observed** · Reviewed 2026-10-15
Chains: Ethereum, Polygon, BNB Smart Chain · Networks: Mainnet, Testnet

Contracts route checkout skimmers to changing off-chain infrastructure.

## Analysis procedure

### Collect

Injected browser script, resolver/hosting contract response, skimmer code and transfer telemetry.

### Inspect

Recover the destination and distinguish plaintext/encrypted variants; identify enabled collection and transmission paths.

### Correlate

Match card-field access to actual HTTP/WebSocket sends when captured; separate contacted hosts from staged hosts.

### Interpretation limits

Contract routing does not mean card data is stored on-chain. Alternative code paths are not confirmed transfers.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

Sources document Sepolia and Polygon pointers plus BSC script delivery. The browser captures payment data; HTTP image-like requests or WebSockets move it off-chain. This record does not claim card data is written to the blockchain. Confiant’s HexMage builds enable Fetch-GET collection; WebSocket, beacon and image-pixel alternatives are code capabilities. Its 20 traffic-associated delivery hosts and 35 merely staged hosts have different evidence.

Examples: Sepolia / Polygon Magecart; BSC JavaScript card skimmer; HexMage

### Detection guidance

Inspect unexpected checkout RPC calls, external scripts, form or DOM interception and subsequent data-bearing HTTP or WebSocket traffic.

### Defensive approach

Review checkout script integrity and approved destinations. Target the confirmed contract/resource and the off-chain collection path.

## ATT&CK assessment

Enterprise · Technique · Reported behavior

Contract-supplied pointers fit Dead Drop Resolver. Checkout input capture is scoped to the Collection objective of T1056. Off-chain data removal is associated with Exfiltration at tactic level because HTTP and WebSocket paths vary by report.
