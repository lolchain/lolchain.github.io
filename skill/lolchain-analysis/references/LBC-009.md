## Analysis procedure

### Collect

Visitor UUID/cookie, contract request, any transaction and the schema of telemetry fields.

### Inspect

Identify whether the code checks a flag or writes IP/visitor data. Preserve field-level decoded evidence and transaction status.

### Correlate

Link a specific visitor check/write to browser-session timestamps without exposing unnecessary personal data in the report.

### Interpretation limits

A getter check is not a write. UUID de-duplication is not automatically IP or file exfiltration; raw counts are not unique victims.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

INDA documents BSC-testnet victim IP telemetry. Expel separately analyzes a contract used to check visitor UUIDs during delivery. Distinguish a duplicate-visitor flag from an IP-bearing public record, and do not interpret raw ledger counts as unique infected devices. Talos reconstructs cjs_id visitor checks during ClearFake delivery; a cookie UUID check alone does not establish stolen-file or IP exfiltration.

Examples: ClearFake testnet tracker

### Detection guidance

Hunt unexpected testnet writes and preserve transaction input data as potentially sensitive incident evidence.

### Defensive approach

Restrict unsanctioned testnet access; remove the loader. Public victim records may persist after remediation.

## ATT&CK assessment

Enterprise · Tactic only · Reported behavior

Tactic-level association only for off-host disclosure of victim IP and identifying telemetry. A generated UUID or duplicate-visitor check alone is not evidence of stolen-data exfiltration. No specific exfiltration technique is asserted.

- [TA0010 · Exfiltration](https://attack.mitre.org/tactics/TA0010/)
