## Analysis procedure

### Collect

Candidate transaction outputs, integer satoshi values and the amount-to-address logic.

### Inspect

Apply the documented output selection, numeric conversion and byte order; retain a reproducible calculation.

### Correlate

Compare the proposed IP with destination connections and recovery timing from the host.

### Interpretation limits

Do not decode arbitrary payments into IPs or use floating-point amounts. A plausible address alone is weak evidence.

Methods: [Bitcoin transaction channels](bitcoin.md).

## Catalog context

Published investigations describe converting Bitcoin transaction amounts into a backup C2 IP. RTM also used alternative naming. Historical APIs and current RPC services should not be assumed interchangeable.

Examples: Akamai cryptomining botnet; RTM

### Detection guidance

Correlate explorer requests with outbound connections to newly seen IPs. URL reputation alone does not reveal the encoded destination.

### Defensive approach

Baseline explorer traffic from servers and shell processes; block validated downstream infrastructure.

## ATT&CK assessment

Enterprise · Technique · Reported behavior

Explorer-accessed transaction values recover a backup C2 IP. This is a pointer and fallback mechanism; it is not DNS tunneling.

- [TA0011 · Command and Control](https://attack.mitre.org/tactics/TA0011/)
