# LBC-012 · Content-addressed payload and phishing hosting

Evidence: **Observed** · Reviewed 2026-10-15

HTTP gateways expose content addressed by CID across multiple providers.

## Analysis procedure

### Collect

CID, optional path, gateway form, HTTP response and payload/page bytes.

### Inspect

Parse path/subdomain addressing; preserve the CID and inert bytes plus file hash without rendering the page.

### Correlate

Match the artifact to download, execution or credential-collection telemetry and any subsequent destination.

### Interpretation limits

Gateway ownership is not uploader attribution. Content hosting does not establish that credentials or files were exfiltrated over IPFS.

Methods: [IPFS, IPNS and Arweave](content.md).

## Catalog context

IPFS HTTP gateways expose CID-addressed files and phishing pages. Reports show binaries, scripts and a VHD. The same CID can be served through different path or subdomain gateways. Phishing credentials and subsequent malware traffic commonly leave through conventional endpoints; hosting does not establish IPFS exfiltration.

Examples: Dark Utilities; TransferLoader; DEAD#VAX; AsyncAPI; IPFS phishing

### Detection guidance

Extract and normalize CIDs from /ipfs/ paths and subdomain gateways; correlate downloads with execution.

### Defensive approach

Block validated CIDs or resources across gateways; baseline shared gateway use and self-hosted peers.
