Evidence: **Observed** · Reviewed 2026-10-16
Chains: TRON, Aptos, BNB Smart Chain · Networks: Mainnet

Different chains provide redundant pointers to a payload stored on another chain.

## Analysis procedure

### Collect

TRON/Aptos lookup responses, fallback order and the BSC transaction pointer returned by each route.

### Inspect

Preserve each hop as a separate chain/network/object; retrieve the BSC input and follow the evidenced decryption.

### Correlate

Build the observed route and identify which fallback branch actually executed before the off-chain stage.

### Interpretation limits

Use chain-native parsing for TRON and Aptos; EVM RPC examples apply only to the BSC stage. Do not infer transfers or bridges between chains.

Methods: [Cross-chain routing](cross-chain.md), [EVM contracts and transaction data](evm.md).

## Catalog context

The loader tries a TRON transaction route, then Aptos on failure. Both point to BSC transaction input holding encrypted instructions or configuration. Decryption leads to off-chain infrastructure. Chainalysis associates the deployer with UNC5342; this is its attribution assessment.

Examples: UNC5342-linked redundant TRON / Aptos routes, per Chainalysis

### Detection guidance

Correlate ordered TRON-to-Aptos fallback with BSC transaction lookups, then downstream connections. Preserve transaction identifiers and decoded pointer relationships; normal traffic on any one chain is insufficient.

### Defensive approach

Contain the loader and validated downstream services. Review alternate RPC routes and self-hosted nodes; provider lists alone cannot guarantee disruption across every route.
