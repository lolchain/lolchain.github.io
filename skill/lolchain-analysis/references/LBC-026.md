# LBC-026 · Contract-backed platform-specific delivery

Evidence: **Observed** · Reviewed 2026-10-16
Chains: BNB Smart Chain, Ethereum · Networks: Mainnet, Testnet

A staged contract lookup selects the payload appropriate to the victim platform.

## Analysis procedure

### Collect

First-stage request, subsequent contract/selectors and captured platform detection/branch logic.

### Inspect

Record each return value and contract hop on its actual network; preserve which platform branch was chosen.

### Correlate

Connect the selected platform payload with browser/OS evidence and subsequent execution artifacts.

### Interpretation limits

Several contracts on one network are not automatically cross-chain routing. Unselected platform branches remain code capabilities.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

Expel and VMRay describe contract chains on BSC testnet, including platform routing. Checkmarx documents platform-specific payload retrieval through Ethereum-backed npm execution. A contract chain is an application workflow, not necessarily cross-chain routing.

Examples: ClearFake; contract-backed npm loaders

### Detection guidance

Correlate consecutive getters, selectors, OS checks and a subsequent executable download. Include testnet egress in baselines.

### Defensive approach

Capture the complete lookup chain and downstream files. A single blocked stage may be replaced; remove the injected loader or package.

## ATT&CK assessment

Enterprise · Technique · Reported behavior

The staged contract workflow selects and retrieves a platform-specific payload. The mapping concerns transfer into the victim environment, not the number of contracts used.

- [TA0011 · Command and Control](https://attack.mitre.org/tactics/TA0011/)
- [T1105 · Ingress Tool Transfer](https://attack.mitre.org/techniques/T1105/)
