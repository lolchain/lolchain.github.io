# LBC-019 · Ransomware communication proxy discovery

Evidence: **Observed** · Reviewed 2026-10-16
Chains: Polygon · Networks: Mainnet

A ransom-note application retrieves a communication proxy through a contract.

## Analysis procedure

### Collect

Polygon getter request, returned messaging-proxy address and fallback RPC configuration.

### Inspect

Reproduce the pointer read and any decode at the incident block; retain state changes over the relevant window.

### Correlate

Connect the resolved proxy to captured victim–operator communication metadata.

### Interpretation limits

The message relay is off-chain. A pointer does not show message contents, and configured RPCs do not prove use.

Methods: [EVM contracts and transaction data](evm.md).

## Catalog context

Group-IB documents a Polygon contract that supplies a proxy for victim–operator messaging, with fallback RPC services. The message relay remains off-chain.

Examples: DeadLock

### Detection guidance

Investigate ransom-note HTML traffic and Polygon lookups in affected hosts. Preserve returned proxy URLs.

### Defensive approach

Block validated proxy resources and contain the intrusion. Shared RPC blocks can affect legitimate applications.

## ATT&CK assessment

Enterprise · Tactic only · Reported behavior

Contextual association with the extortion workflow. The retrieved proxy supports victim–operator negotiation; that alone is not command and control of a compromised system. No C2 sub-technique is assigned.

- [TA0040 · Impact](https://attack.mitre.org/tactics/TA0040/)
